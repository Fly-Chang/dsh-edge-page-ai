# BUG-011 双击批处理脚本中文注释在 GBK 控制台被误解码导致命令执行失败

- 状态: closed
- 严重程度: S1 阻断
- 发现时间: 2026-08-16 21:55 +08:00
- 发现人: 用户实测反馈
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 中文版 / cmd 代码页 936 / edge-page-ai 0.1.0-dev
- 关联功能/文件: `scripts/stop-gateway.bat`、`start-gateway.bat`、`open-bookmarklet.bat`

## 现象描述

双击 `scripts\stop-gateway.bat` 后报错：

```text
'...powershell' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

## 复现步骤

1. 在中文 Windows 的 cmd（代码页 936）中运行 `scripts\stop-gateway.bat`。
2. 观察错误。

## 实际结果

中文 `rem` 注释被 GBK 误解码；原 UTF-8 中文句号（`E3 80 82`）与 CRLF 中的
`0D` 被合并为 GBK 双字节字符，导致注释行与下一行 `powershell` 命令粘连，
cmd 把注释尾部和 `powershell` 当作同一命令解析，报“不是内部或外部命令”。

## 期望结果

双击脚本直接执行，输出 `[edge-page-ai] gateway stopped.`。

## 原因分析

1. 批处理文件以 UTF-8（无 BOM）保存，中文 Windows cmd 默认按 ANSI/GBK 解码。
2. UTF-8 中文标点与 CRLF 的字节在 GBK 解码时发生错位，把换行中的 `0D` 吃掉，
   造成 `rem` 注释吞并下一行命令。
3. PowerShell `.ps1` 与 VBS 脚本同样存在编码风险，一并进行处理。

## 修复方案

1. 所有批处理/VBS/PS1 启动脚本改为 **纯 ASCII**（英文注释与提示），避免代码页依赖。
2. 统一保存为 **ASCII + CRLF** 行尾。
3. 实测 `stop-gateway.bat`：成功停止网关并输出预期信息。
