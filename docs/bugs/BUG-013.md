# BUG-013 外部网页点击书签提示“无法连接 DSH 网关”

- 状态: resolved
- 严重程度: S1 阻断
- 发现时间: 2026-08-16 22:10 +08:00
- 发现人: 用户实测反馈
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Edge 151 / edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/gateway/app.js`、`src/gateway/client/injected-page.mjs`、`src/edge-bridge/content.js`

## 现象描述

本地示例页（`http://127.0.0.1:8000`）书签翻译正常；切换到其他网站后点击书签，
弹出“无法连接 DSH 网关：请确认 npm start 正在运行，然后重试”。经检查网关实际在运行，
`/v1/health` 返回 200。

## 复现步骤

1. 确认本地网关运行中。
2. 打开任意非 127.0.0.1 的外部网站（严格 CSP 或公网 HTTPS 页面）。
3. 点击书签。

## 实际结果

`bootstrap.js` 的 `<script>` 元素触发 `onerror`，提示无法连接网关。

## 期望结果

普通外部页面也能打开面板并翻译；确实被浏览器安全策略拦截时，提示信息应说明真实原因。

## 原因分析

网关正常，因此是**页面侧安全策略**拦截了对 `http://127.0.0.1:8787` 的脚本加载，
已知两类候选：

1. 页面 CSP `script-src` 不允许 127.0.0.1（见 BUG-005）。
2. 浏览器 Private/Local Network Access 策略：公网/外部源页面向本地回环地址发起的
   脚本或模块请求可能被拦截。

书签模式在页面主世界工作，受上述策略限制，属于浏览器硬边界；Edge 薄壳扩展的
content script 拥有 `host_permissions`，可以在隔离世界直连 127.0.0.1，绕过页面 CSP。

## 修复方案

1. Edge 薄壳扩展改为**隔离世界方案**（不再向页面注入 `<script>`）：
   - content script 通过 `chrome.storage` 读取 token；
   - `import(chrome.runtime.getURL('bridge-client.bundle.mjs'))` 在隔离世界加载客户端；
   - 客户端直接 fetch 网关（host_permissions 放行 CORS）；
   - UI 插入 shadow/DOM 容器，不受页面 CSP 脚本限制。
2. 新增 `scripts/build-page-client.mjs` 本地模块打包器，生成自包含
   `src/edge-bridge/bridge-client.bundle.mjs`。
3. 书签模式保留为零安装演示入口；被 CSP/PNA 拦截时给出更准确的提示文案（后续跟进）。
