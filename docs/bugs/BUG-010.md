# BUG-010 带 UTF-8 BOM 的 config.local.json 被误判为不存在并整文件覆盖

- 状态: closed
- 严重程度: S1 阻断
- 发现时间: 2026-08-16 21:48 +08:00
- 发现人: edge-page-ai 开发
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Windows PowerShell 5.1 / Node v22.19.0
- 关联功能/文件: `src/gateway/config.js`、`tests/gateway/config.test.js`

## 现象描述

使用 Windows PowerShell 5.1 `Set-Content -Encoding UTF8` 写入 `config.local.json` 后，
`loadConfig` 把该文件当作不存在，重新生成网关 token 并按 `config.example.json` 重置
模型配置。表现：网关 token 随机变化（旧书签全部失效）、`model.provider` 被重置为 mock。

## 复现步骤

1. 用 Windows PowerShell 5.1 以 UTF8 编码写入 `config.local.json`（文件头带 BOM）。
2. 运行 `node src/gateway/server.js` 或 `node scripts/get-bookmarklet-url.mjs`。
3. 观察 token 变化、provider 变为 mock。

## 实际结果

配置被整文件覆盖，用户已有书签与模型配置丢失。

## 期望结果

带 BOM 的 JSON 应正常读取；配置损坏时应明确报错，而不是静默覆盖。

## 原因分析

1. `JSON.parse` 不能解析文件开头的 BOM 字符 `\uFEFF`，`readJson` 捕获异常后返回 null。
2. `loadConfig` 无法区分“文件不存在”和“文件存在但无法解析”，均按无本地配置处理，
   触发 token 自动生成并写回本地文件，造成覆盖。

## 修复方案

1. `readJson` 在解析前移除 UTF-8 BOM。
2. `loadConfig` 通过 `existsSync` 区分文件不存在与解析失败；解析失败直接抛错，
   明确提示“拒绝覆盖 config.local.json”。
3. 新增测试：BOM 兼容、非法 JSON 拒绝覆盖。
4. 已手动把 `config.local.json` 恢复为原 token 与 DeepSeek 配置（无 BOM）。
