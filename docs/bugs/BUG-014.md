# BUG-014 后台启动的网关进程未继承用户级 DSH_MODEL_API_KEY，导致“模型未配置或不可用”

- 状态: closed
- 严重程度: S1 阻断
- 发现时间: 2026-08-16 22:20 +08:00
- 发现人: 用户实测反馈
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Node v22.19.0 / edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/gateway/config.js`

## 现象描述

页面面板显示“模型未配置或不可用，请检查 config.local.json”。检查后确认：

- 网关运行中；
- `DSH_MODEL_API_KEY` 已在用户环境变量中设置；
- `config.local.json` 的 `apiKey` 为空（符合“密钥放环境变量”的设计）。

## 复现步骤

1. 在 PowerShell 中用 `[Environment]::SetEnvironmentVariable('DSH_MODEL_API_KEY', ..., 'User')`
   设置用户级密钥。
2. 由一个**早于该设置启动的进程**（或未刷新环境的工具进程）启动网关。
3. 页面发起翻译。

## 实际结果

`process.env.DSH_MODEL_API_KEY` 为空，网关按 `apiKey: ''` 请求模型失败，
返回 `MODEL_UNAVAILABLE`。

## 期望结果

即使用户级环境变量是新设置的，启动脚本（尤其后台/服务进程）也应读到密钥。

## 原因分析

`loadConfig` 只读取当前进程的 `process.env`。Windows 用户级环境变量写入注册表
`HKCU\Environment` 后，只有之后启动并继承刷新环境的新进程才能看到；由旧工具会话
后台启动的 node 进程没有继承，导致密钥缺失。

## 修复方案

1. `config.js` 新增 `readUserEnvironment(name)`：通过
   `reg query HKCU\Environment /v <name>` 读取用户级环境变量作为回退。
2. 所有 `DSH_*` 环境变量在 `process.env` 为空时回退读取用户级注册表值；
   进程环境变量优先级更高。
3. `loadConfig` 增加 `userEnvFallback` 选项（默认开启），测试中可关闭以便隔离。
4. 配置测试全部改为显式关闭回退，避免依赖真实机器上的用户环境。
