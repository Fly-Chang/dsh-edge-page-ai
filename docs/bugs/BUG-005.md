# BUG-005 严格 CSP 页面拦截书签与薄壳注入的脚本

- 状态: in-progress
- 严重程度: S2 严重
- 发现时间: 2026-08-16 20:15 +08:00
- 发现人: edge-page-ai 开发
- 处理人: -
- 发现环境: Windows 11 / Edge（任意受支持版本）/ edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/gateway/client/injected-page.mjs`、`src/gateway/app.js`、`src/edge-bridge/content.js`

## 现象描述

部分站点（严格 `Content-Security-Policy` 的 `script-src`，例如某些银行、开发者门户）
会拦截 bookmarklet 注入的 `<script src="http://127.0.0.1:8787/v1/bootstrap.js">`
以及薄壳扩展注入的 `<script type="module" src=".../v1/client.mjs">`，
导致面板不出现、无法翻译。

## 复现步骤

1. 启动本地网关并完成书签/薄壳 token 配置。
2. 打开一个响应头含 `Content-Security-Policy: script-src 'self'`（不含 127.0.0.1）的页面。
3. 点击书签或触发薄壳注入。

## 实际结果

控制台出现 CSP 拒绝外部脚本错误，页面不出现 DSH 面板。

## 期望结果

面板可用；至少翻译功能应能在严格 CSP 页面工作。

## 原因分析

浏览器页面上下文加载外部脚本受页面 CSP 约束，这是浏览器的预期安全行为。
当前两个入口都依赖“向页面 DOM 追加 script 标签”的方式，因此被同等拦截。

## 修复方案

待定（计划 Phase 2 评估）：

1. 薄壳扩展改为在隔离世界（content script）直接调用翻译核心操作 DOM，不使用页面 script 标签；
   扩展可通过 host_permissions 访问 localhost，绕开页面 CSP。
2. 书签模式受 CSP 限制属于浏览器硬边界，无法完全规避；可检测失败并给出明确提示。
3. 网关增加对页面 CSP 的探测提示（由页面客户端无法运行时无从报告，需薄壳侧探测）。
