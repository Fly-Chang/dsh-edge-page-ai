# BUG-008 面板关闭后再次点击书签不显示；更换页面后偶发不显示

- 状态: closed
- 严重程度: S2 严重
- 发现时间: 2026-08-16 21:00 +08:00
- 发现人: 用户实测反馈
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Edge 151 / edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/gateway/app.js`、`src/gateway/client/injected-page.mjs`

## 现象描述

1. 书签可正常首次注入并显示面板。
2. 手动关闭面板后，在同一页面再次点击书签没有任何反应，必须刷新页面才能再次出现。
3. 打开面板后更换页面再点击书签，偶发面板不显示（待提供页面 URL 进一步确认）。

## 复现步骤

1. 启动最新网关，在示例页点击书签，面板出现。
2. 点击面板右上角 × 关闭。
3. 不刷新页面，再次点击同一书签。
4. 观察无面板出现。

## 实际结果

关闭后再次点击无反应。headless 复现日志：

```text
first panel true
after close panel false flag undefined
after reinject panel false flag true
```

## 期望结果

关闭后再次点击书签，面板应立即重新显示；更换普通 http/https 页面后首次点击也应显示。

## 原因分析

1. 旧关闭逻辑 `root.remove()` 把面板从 DOM 删除，同时清除了注入标志。
2. 再次点击书签时虽然重新注入了 `client.mjs`，但 **URL 完全相同**；浏览器模块映射
   （module map）认为该模块在当前文档已求值，不会二次执行，因此不会再创建面板。
3. 这正是“刷新页面才能恢复”的原因：刷新后新文档的 module map 为空。
4. “更换页面不显示”部分暂未在 headless 中复现（普通整页导航会创建新文档，理论上不受
   该问题影响），怀疑与 BFCache/SPA 同文档导航、严格 CSP 页面（BUG-005）或仍在使用
   旧书签有关，需用户提供页面 URL 与 Console 报错继续定位。

## 修复方案

1. 面板关闭改为**隐藏**（`display:none`）而非移除，保留模块实例与面板 DOM。
2. 书签代码与 `bootstrap.js` 在检测到面板已存在时，直接
   `p.style.display=''` 恢复显示，不重复注入。
3. 注入脚本增加 `data-dsh-bootstrap="1"` 标记，防止加载期间重复注入；加载成功/失败
   后移除标记。
4. `bootstrap.js` 给 `client.mjs` 增加 `&r=Date.now()` 缓存破坏参数：即使面板被外部
   代码移除，再次点击也能强制加载新模块实例。
5. 页面客户端顶部对“已有全局实例但面板 DOM 缺失”的情况做自动恢复。
