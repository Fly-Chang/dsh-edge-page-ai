# BUG-002 占位符保护产生嵌套占位符

- 状态: closed
- 严重程度: S1 阻断
- 发现时间: 2026-08-16 20:07 +08:00
- 发现人: edge-page-ai 开发
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Node v22.19.0 / edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/core/placeholder-protector.js`、`tests/core/placeholder-protector.test.js`

## 现象描述

`protect("Open https://example.com/a?b=1 and mail me@example.com...")` 的输出为
`Open [[[[2]]]] and mail [[[[3]]]]...`，占位符互相嵌套，还原逻辑失效。

## 复现步骤

1. `node -e "import('./src/core/placeholder-protector.js').then(m => console.log(m.protect('Open https://example.com/a?b=1 and mail me@example.com. Price is 42.5 USD.')))"`
2. 观察 protectedText。

## 实际结果

出现 `[[[[2]]]]`、`[[[[3]]]]` 嵌套 token。

## 期望结果

只出现单层 token，如 `[[0]]`、`[[1]]`。

## 原因分析

原实现按模式列表**分轮**执行 `String.replace`；后续数字模式会重新扫描前面替换产物
`[[0]]` 中的数字 `0`，把 token 内部数字再次保护，形成嵌套。

## 修复方案

将所有保护模式合并为单一正则（按 URL → 邮箱 → 代码 → 数字的长串优先顺序），
单次 `replace` 执行。JS `replace` 不会重扫替换产物，因此已生成的 `[[n]]` 不再被处理。
同时收紧邮箱正则，避免吞掉句尾点号。
