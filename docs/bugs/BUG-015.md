# BUG-015 手动模式后，已打开的旧页面无法调出面板

- 状态: resolved
- 严重程度: S1 阻断
- 发现时间: 2026-08-16 22:40 +08:00
- 发现人: 用户实测反馈
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Edge 151 / edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/edge-bridge/background.js`、`content.js`、`manifest.json`

## 现象描述

扩展改为手动激活后，点击工具栏图标或按快捷键没有任何反应，面板不出现。

## 复现步骤

1. 页面在扩展更新/重载之前已经打开。
2. 在 `edge://extensions` 重载扩展。
3. 回到旧页面点击扩展图标。

## 实际结果

无面板、无提示。

## 期望结果

无论页面是否在扩展重载前打开，点击图标/快捷键都应调出面板。

## 原因分析

扩展重载后，旧页面里的 content script 上下文失效；后台
`chrome.tabs.sendMessage` 抛出“Receiving end does not exist”，代码只做了
静默 catch，没有补救注入，因此点击无反应。

## 修复方案

1. 后台 `toggleInTab` 改为两次尝试：第一次 sendMessage 失败时，用
   `chrome.scripting.executeScript` 按需注入 `content.js`，再发送一次消息。
2. `manifest.json` 增加 `scripting` 权限。
3. `content.js` 增加 `__DSH_BRIDGE_CONTENT_LOADED__` 防重复注入守卫，
   避免声明式注入 + 按需注入导致重复监听、面板被连续 toggle 两次。
4. 测试断言：content 守卫存在、manifest 含 scripting 权限。
