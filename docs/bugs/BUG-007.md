# BUG-007 注入失败或面板关闭后 bootstrap 标志残留，再次点击书签无反应

- 状态: closed
- 严重程度: S2 严重
- 发现时间: 2026-08-16 20:45 +08:00
- 发现人: 用户实测反馈（点击书签无反应）
- 处理人: edge-page-ai 开发
- 发现环境: Windows 11 / Edge / edge-page-ai 0.1.0-dev
- 关联功能/文件: `src/gateway/app.js`、`src/gateway/client/injected-page.mjs`

## 现象描述

书签地址已正确（不再跳转说明页），但在页面点击书签没有任何反应：
无面板、无错误提示。刷新页面后可能恢复。

## 复现步骤

1. 首次点击书签时网关未启动，或 `client.mjs` 加载失败。
2. 修复网关后，在同一页面再次点击书签。
3. 或者：正常打开面板后点击 × 关闭，再点击书签尝试重新打开。

## 实际结果

第二次点击完全无反应。

## 期望结果

每次点击都应重新注入，或给出可见的错误提示；失败后再次点击可以重试。

## 原因分析

书签代码与 `bootstrap.js` 在**实际加载脚本之前**就写入
`window.__DSH_BOOTSTRAPPED__ = true` 作为防重复注入标志：

1. 当 bootstrap/client 脚本加载失败时，标志没有被清除，后续点击直接命中
   `if(window.__DSH_BOOTSTRAPPED__)return;` 静默退出；
2. 面板关闭按钮只清除了 `window.__DSH_PANEL__`，没有清除 bootstrap 标志，
   关闭后无法再次用书签打开面板。

## 修复方案

1. 书签代码与 `bootstrap.js` 的防重复判断改为：
   `if(window.__DSH_BOOTSTRAPPED__ && document.getElementById('dsh-page-ai-panel')) return;`
   即只有“标志存在且面板确实在页面上”才跳过；标志残留但面板不存在时自动清除并重新注入，
   无需刷新页面。
2. 书签代码与 `bootstrap.js` 给注入的 `<script>` 增加 `onerror`：
   清除 `window.__DSH_BOOTSTRAPPED__` 并 `alert` 明确错误原因。
3. 页面客户端初始化包在 try/catch 中：失败时清除标志并提示。
4. 面板关闭时同时清除 `__DSH_PANEL__` 与 `__DSH_BOOTSTRAPPED__`，允许再次点击书签重开。
5. 集成测试新增断言：说明页与 bootstrap 均包含 `onerror`、标志清除与面板存在性判断。
