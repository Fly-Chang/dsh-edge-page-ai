# 04 缺陷记录模板与管理规范

- 文档编号: PM-04
- 版本: 1.0.0
- 状态: 生效
- 生效日期: 2026-08-16

## 1. 管理规则

1. 缺陷统一存放在 `docs/bugs/`，文件名为 `BUG-NNN.md`（NNN 三位递增，如 `BUG-001.md`）。
2. 每个缺陷一个文件；一个文件只描述一个缺陷。
3. 状态机：`open → in-progress → resolved → closed`；不允许 `resolved` 后直接修改历史。
4. 同一编号永久有效，关闭后不复用。
5. 复现步骤必须让另一个开发者在不询问作者的情况下按步骤复现。
6. 缺陷修复提交信息必须包含 `BUG-NNN` 编号。

## 2. 状态说明

| 状态 | 含义 |
| --- | --- |
| open | 已记录，未开始处理 |
| in-progress | 正在处理 |
| resolved | 已修复或已规避，等待验证 |
| closed | 验证通过，关闭 |

## 3. 严重程度

- `S1 阻断`：核心功能不可用。
- `S2 严重`：核心功能可用但主要场景受损。
- `S3 一般`：次要功能异常，存在可接受规避方式。
- `S4 轻微`：文案/样式/易用性问题。
